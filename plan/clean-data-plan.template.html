01 / THREE LEVELS

Mạnh hơn bằng độ phủ.

Mức càng cao càng có nhiều loại dữ liệu, không giảm bảo vệ. File đang dùng hoặc chưa biết chủ sở hữu vẫn được giữ. Dung lượng thu hồi phụ thuộc máy thực tế.

01 · MẶC ĐỊNH

Tiêu chuẩn

Thích hợp dọn định kỳ các nhóm cache/temp đã nhận diện.

  • User temp ≥7 ngày.
  • Log rotate ≥30 ngày.
  • Disk cache browser đã đóng.
User scope · không UAC mặc định

Giữ đăng nhập, password, history, source và dữ liệu cá nhân.

02 · ĐỀ XUẤT CHO DỌN SÂU

Chuyên sâu

Mở rộng cache hệ thống và công cụ, kèm kiểm tra điều kiện.

  • Temp Windows, dump/report cũ.
  • Delivery Optimization hợp lệ.
  • Dev cache và servicing: duyệt riêng.
Một số provider cần UAC

Không xóa cache sửa chữa, không dừng update/build để ép dọn.

03 · DUYỆT TỪNG NHÓM

Tối đa có duyệt

Tìm thêm các mục lớn cần quyết định, không tự tick dữ liệu rủi ro.

  • Bộ cài tải về cũ, bin của user.
  • Ứng viên AppData đã gỡ.
  • Windows.old qua Windows.
Backup / xác nhận tác động

Có thể mất dữ liệu app hoặc rollback; không có Undo cho mọi loại.

POLICY CHUNG / MEMORY + DISK

An toàn không popup. Rủi ro đúng mục.

Quét/tìm file không cảnh báo. Chỉ mục rủi ro đã chọn mới yêu cầu duyệt; admin và confirm nhiều lần không mở khóa mục bị chặn.

✓ An toàn · 0 popupCache ổn định/tái tạo được, empty folder đã revalidate, cache app đã gỡ có owner/no-live-dependency xác minh. Chạy trực tiếp và báo kết quả.
◇ Cần duyệtLog/dump cần giữ, dev cache, bộ cài cá nhân, app data có backup. Bỏ tick; hiện tác động và xác nhận phạm vi thật sự được chọn.
! Nguy hiểm · hai bướcWindows.old, database/save/VM xóa vĩnh viễn. Duyệt từng mục + hậu quả trước; final ack/gõ phrase sau. Đổi scope làm approval hết hiệu lực.

◆ Bị chặn · không override

Installer/repair store, protected Windows, cloud/source, file đang dùng hoặc owner/identity chưa rõ. Không takeown/ACL hoặc force-unlock để biến thành rác.

App đã gỡ: dọn phần còn sót phù hợp

Owner/vendor khớp inventory, không còn process/service/task dùng: cache và folder rỗng được dọn trực tiếp, không popup. Database/settings/save hoặc nội dung chưa biết giá trị vẫn cần duyệt; thiếu uninstall key chưa đủ để auto-delete.

Folder rỗng phải còn rỗng khi thực thi; có child mới thì bỏ qua, không xóa đệ quy.

Tìm file lớn / file cũ

Known Folders hoặc root bạn chọn, threshold đề xuất512 MB, tuổi/type/path filters, sort giảm dần, logical/allocated size và dedupe File ID. Source/cloud/system vẫn bị bảo vệ.

Hiện ISO/bộ cài/video/backup/VM kèm tác động; không suy ra không quan trọng từ size/tuổi. File cá nhân bỏ tick, cần chọn cụ thể. Preview folder/property hoặc gợi ý chuyển sang ổ khác.

Windows Cleanup recommendations cũng có nhóm large/unused files; rule risk của app là thiết kế riêng.

03 / ARCHITECTURE

Giữ GUI nhẹ, tách quyền xóa.

PowerShell 5.1 + WPF trước; runspace và native file identity helper. Quét và thực thi có contract riêng, không chạy lệnh xóa trực tiếp từ nút giao diện.

WPF · RAM / CPU | Clean C:→Coordinator / cancellation→Providers + policy→Preview manifest→User / UAC helper→Journal + measurement + restore

Chỉ một operation RAM Clear / Disk Clean cùng lúc. Bounded event queue, danh sách phân trang; mục tiêu scanner ≤150 MB, 2 workers — chưa có đo hiệu năng.

DiscoveryOS volume, Known Folders, SID, vendor profiles, registry/MSIX inventory. Không quét toàn C: mù quáng.
Policy / ownershipAllowlist root + retention + evidence. Unknown/shared/portable được bảo vệ; thiếu uninstall key không đủ.
Immutable planFile ID, volume ID, policy hash, tác động, backup, TTL 10 phút. Đổi phạm vi phải tạo plan mới.
Privilege helperUAC hợp lệ, action allowlist, independently validate. Helper user-writable không phải security boundary.
Executor / recoveryRevalidate, journal trước side effect, copy/hash-verify trước xóa nguồn; cancel ở ranh giới an toàn.
Honest resultPartial/skipped/failed/delegated rõ ràng. Unknown size giữ unknown; không lấy logical size làm free disk.

Chi tiết contract, trust model và cấu trúc file đề xuất: CLEAN_DATA_ARCHITECTURE.md.

04 / EXECUTION LOGIC

Quét → duyệt → kiểm tra lại → dọn.

Quét có giới hạn

Không follow junction/symlink/cloud placeholders; báo thiếu quyền, đang ghi, locked và app còn chạy. Không kill app để giải phóng file.

Xem trước và quyết định

Category/file preview, tác động, evidence, size chưa rõ; nhóm rủi ro bỏ tick. AppData chọn backup khác ổ hoặc xóa vĩnh viễn sau duyệt.

Xin UAC khi thực sự cần

Từ chối UAC → giữ nhóm user đủ điều kiện; không giả success. Privileged helper kiểm tra độc lập caller/policy/manifest.

Thực thi theo danh sách đã duyệt

Revalidate File ID/parent chain và trạng thái; file bị đổi bỏ qua. Backup được hash-verify trước xóa; journal xử lý crash/restart.

Tiến trình, dừng và kết quả

Indeterminate khi scan/native provider, X/N khi xử lý file; elapsed, category hiện tại, cancel boundary. Kết thúc có timestamp và partial/skip/error.

Thu hồi nhiều mà vẫn rõ rủi ro

  • Allocated bytes khác logical size; hard link không cộng trùng.
  • Cách ly trên C: có thể undo nhưng chưa thu hồi chỗ.
  • Backup sang ổ khác: copy → verify → xóa nguồn.
  • Free C: trước/sau có hoạt động khác, không gán mọi thay đổi cho Clean.
  • Không ResetBase, không xóa WinSxS/Installer thủ công, không sửa ACL.

Servicing theo Microsoft · UAC / admin helper

Tính năng phục hồi

Lịch sử local theo run ID; restore preview, kiểm tra hash và xung đột với dữ liệu mới. Mục xóa vĩnh viễn / OS cleanup không hứa Undo. Không tự purge cách ly 14 ngày.

Restore và UAC thật thuộc triển khai sau; prototype hiện minh họa các lựa chọn và kết quả.

06 / QUYẾT ĐỊNH ĐỀ XUẤT

Chốt trước code thực thi.

Checklist để đọc/chốt phạm vi; thay đổi tick không cấp quyền hoặc chạy công cụ.

Đã chốt qua trả lời trực tiếp: portable quyền user, Windows xử lý system; cho permanent appdata sau hai bước duyệt. Backup đích chỉ cần nếu chọn backup mode. Tick checklist không tự cấp quyền thao tác.

Prototype chung có thể thử gì?

Chuyển Memory/Disk, chọn ba mức từng tab; Memory có trim/close/force mẫu và effects. Disk mô phỏng quyền admin/browser/update, tìm file lớn; quét danh mục, tìm kiếm, xem evidence, duyệt mục rủi ro, chọn backup, preview kế hoạch, chạy/dừng tiến trình và xuất JSON mẫu.

Thử prototype →
Vì sao không auto-xóa mọi AppData cũ?

Portable app, shared vendor và save game có thể không có uninstall key. Inference chỉ tạo ứng viên; unknown luôn giữ, app data cần quyết định.

Cần dọn nhiều nhất thì chọn gì?

Dùng Chuyên sâu cho cache đủ điều kiện; Tối đa để tìm thêm mục lớn và duyệt. Chỉ bỏ dữ liệu còn giá trị khi bạn chấp nhận tác động; không có mức bảo đảm xóa nhiều mà hoàn toàn không mất gì.

Admin có mở mọi bảo vệ không?

Không. UAC chỉ cấp quyền thao tác OS hỗ trợ. Installer/repair data, ACL, file đang dùng và ownership chưa rõ vẫn là giới hạn.
